# Camada de IA como serviço FastAPI fino e stateless

A fase 4b precisa expor o Assistente para um front web sem reimplementar o loop de agente fora do Python. Decidimos publicar a camada de IA como um serviço FastAPI **fino e stateless**: o servidor não guarda sessão — o browser é dono do histórico e o envia a cada request, espelhando a semântica efêmera do CLI (histórico só na memória do processo, descartado ao sair). O streaming de tokens sai por SSE sobre `POST /chat`, com uma ponte `queue.Queue` + thread daemon + gerador síncrono para adaptar o `run_agent_turn` síncrono ao streaming do Starlette sem travar o event loop. Rejeitamos um session store no servidor (adiciona estado, expiração e locks sem ganho nesta fase) e reimplementar o loop de agente em TypeScript (o Python é a fonte da verdade das Ferramentas, do custo e do tratamento de falha).
